# Finans sistemi güvenlik ve yayın notu

1. Main Netlify site and finance host must share `FINANCE_ACCESS_SHARED_SECRET` (minimum 32 random characters).
2. On Netlify, define `FINANCE_APP_URL`, `FINANCE_EDITOR_EMAILS`, and optionally `FINANCE_VIEWER_EMAILS`.
3. Apply D1 migrations through `0005_finance_audit.sql` before accepting writes. The API intentionally blocks writes if the audit table is missing.
4. Production starts with an empty database. Demo records are not loaded.
5. Finance access is accepted only through the short-lived signed Netlify launch link and the resulting secure session cookie. Finance writes require an editor session; viewers are read-only. Every attempted and completed write is recorded with user, role, entity, request ID, and timestamp.
6. The finance engine is management support, not an official ledger, tax return, or loan approval system.
7. POS expected dates skip weekends only. Official holidays must be checked against the bank statement.
8. Current stock is aggregate/basic stock. Multi-lot FEFO and regulated lot traceability are not implemented in this version.
9. Run `npm run test` after every formula or build change. The displayed test report is generated by `npm run test:core`; it is not a daily live claim.
